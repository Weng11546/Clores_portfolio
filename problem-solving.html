Case 01 · Networking

Computer cannot connect to Wi-Fi

Problem

A laptop shows “Connected, no internet” or cannot join the Wi-Fi network at all, while other devices in the same place work normally.

Possible causes

  • Wi-Fi adapter disabled, or airplane mode turned on
  • Outdated or corrupted network driver
  • Incorrect IP configuration (wrong static IP, or no DHCP lease)
  • Router problem (needs restart, MAC filtering, no ISP service)
  • DNS problem (pages do not load but the connection exists)

Diagnostic procedure

  1. Check that airplane mode is off and the Wi-Fi adapter is enabled. Test whether a phone works on the same network.
  2. Run ipconfig /all and check for a valid IP. An address starting with 169.254 means no DHCP lease was received.
  3. Ping the router (ping 192.168.1.1). If it replies, the local link is fine.
  4. Ping a public IP (ping 8.8.8.8). If it replies, the internet works.
  5. Ping a name (ping google.com). If the IP works but the name fails, the cause is DNS.

Solution

  1. Re-enable the adapter and restart the router.
  2. Run ipconfig /release, ipconfig /renew and ipconfig /flushdns.
  3. Set the adapter to obtain IP and DNS automatically, or use DNS 8.8.8.8.
  4. Update or reinstall the driver in Device Manager if the adapter still fails.

Lesson learned

Troubleshoot in layers: device, local network, internet, then DNS. The ping results tell exactly which layer is broken, so I do not waste time changing settings at random.

Case 02 · Hardware & Operating System

Computer runs very slowly

Problem

A computer takes several minutes to boot, programs freeze, and the whole system lags even when only a browser is open.

Possible causes

  • Too many startup programs
  • Disk at 100% usage, or a failing hard drive
  • Not enough RAM for the tasks being run
  • Malware or background updates
  • Low free storage space on the system drive

Diagnostic procedure

  1. Open Task Manager (Ctrl + Shift + Esc) and see which resource is at 100%: CPU, memory or disk.
  2. Check the Startup tab for programs with high startup impact.
  3. Check free space on drive C:. Under about 10% free causes slowdowns.
  4. Run a full antivirus scan.
  5. Run sfc /scannow to check system files and check the drive health status.

Solution

  1. Disable unneeded startup programs.
  2. Delete temporary files and uninstall unused software to free space.
  3. Remove any malware found and finish pending Windows updates.
  4. If the disk or memory remains the bottleneck, replace the hard drive with an SSD or add RAM.

Lesson learned

Measure before fixing. Task Manager shows the real bottleneck, so I fix that one resource instead of reinstalling the whole system. Regular cleanup also prevents the problem from coming back.

Case 03 · Software Development

Android Studio Gradle sync or build fails

Problem

While developing a Kotlin Android app, Android Studio reports “Gradle sync failed” or the build stops with errors, and the app cannot run.

Possible causes

  • Android Gradle Plugin, Gradle and JDK versions that are not compatible
  • A dependency that cannot be downloaded (no internet, proxy or wrong version number)
  • Corrupted Gradle or IDE cache
  • A syntax or import error in the code or in the build.gradle file
  • Missing SDK platform or build tools

Diagnostic procedure

  1. Open the Build tab and read the first error message, not the last. Later errors are usually side effects.
  2. Check whether the error mentions a dependency download, a version conflict or a Java version.
  3. Confirm internet access and that the Gradle JDK in Settings matches what the project needs.
  4. Run ./gradlew build --stacktrace in the terminal for more detail.
  5. Check recent changes: undo the last edit to build.gradle and see whether the error disappears.

Solution

  1. Fix the specific cause: align the plugin, Gradle and JDK versions, correct the dependency version, or install the missing SDK component.
  2. Run Build → Clean Project, then sync again.
  3. If the cache is corrupted, use File → Invalidate Caches / Restart.

Lesson learned

Read the first error and change one thing at a time. Committing working code to Git before upgrading versions lets me roll back quickly when an upgrade breaks the build.

Case 04 · Web Development

Images and styles do not load on my website

Problem

A web page works on my computer, but after uploading it online the photos show as broken icons, or the page appears without its styling.

Possible causes

  • Wrong file path, or the file was not uploaded
  • File name case mismatch (Hero.jpg vs hero.jpg)
  • Wrong or missing file extension (.jpg vs .jpeg)
  • Browser cache showing an old version
  • A typo in the link or script tag

Diagnostic procedure

  1. Open browser DevTools (F12) and go to the Network tab, then reload the page.
  2. Look for red entries with status 404. They list exactly which files are missing.
  3. Compare each failing path with the real file name in the project folder, letter by letter.
  4. Check that the file exists in the repository or hosting folder.
  5. Try a hard refresh (Ctrl + Shift + R) to rule out the cache.

Solution

  1. Rename files and fix the paths so they match exactly, using lowercase names with no spaces.
  2. Upload any missing files and commit them to GitHub.
  3. Hard refresh and re-check the Network tab until no 404 remains.

Lesson learned

Windows ignores letter case in file names, but most web servers do not. I now use consistent lowercase file names and always check the Network tab first, since it names the exact problem.

Case 05 · Application & API Integration

Discord webhook messages are not being sent from the app

Problem

An Android app that sends records to a Discord channel through a webhook runs without crashing, but no message ever appears in Discord.

Possible causes

  • Missing INTERNET permission in AndroidManifest.xml
  • Network call run on the main thread, or its error silently ignored
  • Webhook URL deleted, copied incorrectly or regenerated
  • Invalid JSON payload (HTTP 400) or rate limit reached (HTTP 429)
  • The phone has no internet connection

Diagnostic procedure

  1. Test the webhook outside the app with Postman or curl. If the message appears, the webhook is fine and the bug is in the app.
  2. Log the HTTP response code and body in Logcat. 404 means a wrong or deleted URL, 400 means bad JSON, 429 means too many requests.
  3. Check Logcat for NetworkOnMainThreadException or SecurityException.
  4. Confirm the manifest contains the internet permission and that the device is online.

Solution

  1. Add <uses-permission android:name="android.permission.INTERNET" /> to the manifest.
  2. Move the request into a coroutine on Dispatchers.IO and wrap it in try/catch with logging.
  3. Regenerate the webhook URL if needed and correct the JSON fields.
  4. Wait and retry when the response is 429.

Lesson learned

Never let network errors fail silently: logging the response code turns a mystery into a one-line answer. Also, a webhook URL works like a password, so it should not be shared publicly or committed to GitHub.
