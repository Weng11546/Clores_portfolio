Case 01 · Networking

Computer cannot connect to Wi-Fi

Problem

A laptop shows “Connected, no internet” or cannot join the Wi-Fi network at all, while other devices in the same place work normally.

Possible causes

  • Wi-Fi adapter disabled, or airplane mode turned on
  • Outdated or corrupted network driver
  • Incorrect IP configuration (wrong static IP, or no DHCP lease)
  • Router problem (needs restart, MAC filtering, no ISP service)
  • DNS problem (pages do not load but the connection exists)

Diagnostic procedure

  1. Check that airplane mode is off and the Wi-Fi adapter is enabled. Test whether a phone works on the same network.
  2. Run ipconfig /all and check for a valid IP. An address starting with 169.254 means no DHCP lease was received.
  3. Ping the router (ping 192.168.1.1). If it replies, the local link is fine.
  4. Ping a public IP (ping 8.8.8.8). If it replies, the internet works.
  5. Ping a name (ping google.com). If the IP works but the name fails, the cause is DNS.

Solution

  1. Re-enable the adapter and restart the router.
  2. Run ipconfig /release, ipconfig /renew and ipconfig /flushdns.
  3. Set the adapter to obtain IP and DNS automatically, or use DNS 8.8.8.8.
  4. Update or reinstall the driver in Device Manager if the adapter still fails.

Lesson learned

Troubleshoot in layers: device, local network, internet, then DNS. The ping results tell exactly which layer is broken, so I do not waste time changing settings at random.

Case 02 · Hardware & Operating System

Computer runs very slowly

Problem

A computer takes several minutes to boot, programs freeze, and the whole system lags even when only a browser is open.

Possible causes

  • Too many startup programs
  • Disk at 100% usage, or a failing hard drive
  • Not enough RAM for the tasks being run
  • Malware or background updates
  • Low free storage space on the system drive

Diagnostic procedure

  1. Open Task Manager (Ctrl + Shift + Esc) and see which resource is at 100%: CPU, memory or disk.
  2. Check the Startup tab for programs with high startup impact.
  3. Check free space on drive C:. Under about 10% free causes slowdowns.
  4. Run a full antivirus scan.
  5. Run sfc /scannow to check system files and check the drive health status.

Solution

  1. Disable unneeded startup programs.
  2. Delete temporary files and uninstall unused software to free space.
  3. Remove any malware found and finish pending Windows updates.
  4. If the disk or memory remains the bottleneck, replace the hard drive with an SSD or add RAM.

Lesson learned

Measure before fixing. Task Manager shows the real bottleneck, so I fix that one resource instead of reinstalling the whole system. Regular cleanup also prevents the problem from coming back.

Case 03 · Software Development

Android Studio Gradle sync or build fails

Problem

While developing a Kotlin Android app, Android Studio reports “Gradle sync failed” or the build stops with errors, and the app cannot run.

Possible causes

  • Android Gradle Plugin, Gradle and JDK versions that are not compatible
  • A dependency that cannot be downloaded (no internet, proxy or wrong version number)
  • Corrupted Gradle or IDE cache
  • A syntax or import error in the code or in the build.gradle file
  • Missing SDK platform or build tools

Diagnostic procedure

  1. Open the Build tab and read the first error message, not the last. Later errors are usually side effects.
  2. Check whether the error mentions a dependency download, a version conflict or a Java version.
  3. Confirm internet access and that the Gradle JDK in Settings matches what the project needs.
  4. Run ./gradlew build --stacktrace in the terminal for more detail.
  5. Check recent changes: undo the last edit to build.gradle and see whether the error disappears.

Solution

  1. Fix the specific cause: align the plugin, Gradle and JDK versions, correct the dependency version, or install the missing SDK component.
  2. Run Build → Clean Project, then sync again.
  3. If the cache is corrupted, use File → Invalidate Caches / Restart.

Lesson learned

Read the first error and change one thing at a time. Committing working code to Git before upgrading versions lets me roll back quickly when an upgrade breaks the build.

Case 04 · Web Development

Images and styles do not load on my website

Problem

A web page works on my computer, but after uploading it online the photos show as broken icons, or the page appears without its styling.

Possible causes

  • Wrong file path, or the file was not uploaded
  • File name case mismatch (Hero.jpg vs hero.jpg)
  • Wrong or missing file extension (.jpg vs .jpeg)
  • Browser cache showing an old version
  • A typo in the link or script tag

Diagnostic procedure

  1. Open browser DevTools (F12) and go to the Network tab, then reload the page.
  2. Look for red entries with status 404. They list exactly which files are missing.
  3. Compare each failing path with the real file name in the project folder, letter by letter.
  4. Check that the file exists in the repository or hosting folder.
  5. Try a hard refresh (Ctrl + Shift + R) to rule out the cache.

Solution

  1. Rename files and fix the paths so they match exactly, using lowercase names with no spaces.
  2. Upload any missing files and commit them to GitHub.
  3. Hard refresh and re-check the Network tab until no 404 remains.

Lesson learned

Windows ignores letter case in file names, but most web servers do not. I now use consistent lowercase file names and always check the Network tab first, since it names the exact problem.

Case 05 · Application & API Integration

Discord webhook messages are not being sent from the app

Problem

An Android app that sends records to a Discord channel through a webhook runs without crashing, but no message ever appears in Discord.

Possible causes

  • Missing INTERNET permission in AndroidManifest.xml
  • Network call run on the main thread, or its error silently ignored
  • Webhook URL deleted, copied incorrectly or regenerated
  • Invalid JSON payload (HTTP 400) or rate limit reached (HTTP 429)
  • The phone has no internet connection

Diagnostic procedure

  1. Test the webhook outside the app with Postman or curl. If the message appears, the webhook is fine and the bug is in the app.
  2. Log the HTTP response code and body in Logcat. 404 means a wrong or deleted URL, 400 means bad JSON, 429 means too many requests.
  3. Check Logcat for NetworkOnMainThreadException or SecurityException.
  4. Confirm the manifest contains the internet permission and that the device is online.

Solution

  1. Add <uses-permission android:name="android.permission.INTERNET" /> to the manifest.
  2. Move the request into a coroutine on Dispatchers.IO and wrap it in try/catch with logging.
  3. Regenerate the webhook URL if needed and correct the JSON fields.
  4. Wait and retry when the response is 429.

Lesson learned

Never let network errors fail silently: logging the response code turns a mystery into a one-line answer. Also, a webhook URL works like a password, so it should not be shared publicly or committed to GitHub.

Case 06 · Web Security

SQL injection in a login form

What is the vulnerability

SQL injection happens when user input is placed directly into a database query as part of the SQL command itself, instead of being treated only as data. Because the input can change the structure of the query, an attacker can alter what the database is asked to do. A login form that builds its query by joining the typed username and password into a text string is a common example.

How it can happen

  • SQL statements built by joining or formatting strings with user input
  • Relying only on client-side (browser) validation
  • Detailed database error messages shown to the user, which reveal the query structure
  • Database accounts with more permissions than the application needs

Risks

An attacker may bypass a login, read records they should not see, change or delete data, or expose personal information. In some server setups, the damage can extend beyond the database. Because the flaw sits in a common feature like login or search, a single weakness can affect every user of the application.

Prevention for developers

  1. Use parameterized queries (prepared statements), so the database always treats input as a value: SELECT * FROM users WHERE username = ?, with the input passed separately.
  2. Use the query builder or ORM of the framework in its safe, parameterized form, and avoid raw string concatenation.
  3. Validate input on the server: check type, length and format, and accept only expected values where possible.
  4. Store passwords as salted hashes (for example bcrypt or Argon2), never as plain text.

Security practices

  • Give each application database account only the permissions it needs (least privilege).
  • Show generic error messages to users and log the details on the server.
  • Review code for query construction, and use static analysis tools in the development workflow.
  • Keep frameworks, drivers and the database server updated.
  • Learn the OWASP Top 10 and test only applications you own or have written permission to test.

Lesson learned

SQL injection is prevented by separating code from data. Input validation helps, but parameterized queries remove the entire class of bug, so they should be the default. Security works best in layers: safe code, least privilege, careful error handling and regular review.

Looking back

Reflection

Before entering BSIT, I thought IT mostly meant fixing computers and making websites. My experience was limited to Microsoft Word, Excel and PowerPoint, which I used for school work and administrative tasks. I did not realize how much planning, organization and problem-solving sit behind every app people use.

The most important thing I learned is that technology matters only when it solves a real problem. My projects started with a need, such as a poultry feed business struggling with manual stock records, or people who could not track their spending. The code came after that. I also learned that careful work matters as much as technical skill. In my data analysis project, a few entry errors could have changed my conclusions if I had not checked for them.

The project that taught me the most was the Poultry Feed Stock Tracking with POS Application. It had real users in mind: owners, managers, inventory clerks and cashiers. I had to think about login roles, product search, validation and sales reports all at once. It taught me that a system is a set of connected parts, and that a sale affects stock levels. It also taught me to be honest about limitations and future improvements.

The hardest difficulty involved data and unfamiliar tools. In my Social Media Engagement Analysis, I found text and image posts with video lengths above zero, and most videos had no recorded length. I had to decide what to correct and what I could not conclude. In my app projects, learning Kotlin, Android Studio and Room Database while building meant many moments when nothing would run. I learned to read errors carefully and test one change at a time.

My skills have changed a lot. I started with basic office software. Now I can build web pages, write JavaScript and Python, use SQL, build Android apps, work with Git and GitHub, and analyze data in Excel. More importantly, I break problems into steps, test my assumptions and explain results in plain language.

I still need to improve in backend development, database design and security, because I depended on tools and guidance more than I would like. I also want to improve my testing habits, my clean coding, and my confidence presenting technical ideas to non-technical people.

I want to become an IT Project Manager with a strong foundation in web development and data analysis. Good managers understand the work their teams do, so I want to keep building and analyzing before I lead. I want to connect technical teams with the people they serve and keep projects organized and honest about progress.

I am ready to begin my career because I have already done the work the field requires. I have built real projects, handled messy data, documented my work and finished what I started. I may not have every answer, but I know how to find them, keep learning and work with others. I am not finished growing, and I am ready to begin.

Communication

Good communication means the other person understands the idea the first time, whether they are a teammate, a client or an interviewer. This is how I explain ideas clearly.

How I explain ideas

  1. Know my audience. A client or user wants to know what the system does for them. A teammate needs the technical details. I change my words to fit who is listening.
  2. Start with the problem. I begin with the need, then the solution, then the result.
  3. Use plain language. I say “the system saves each sale and lowers the stock count” instead of technical terms, and I explain any term I cannot avoid.
  4. Give one idea at a time, with an example, a screenshot or a short demo.
  5. Check understanding. I ask if it makes sense, listen to questions, and explain again in a different way when someone is confused.
  6. Confirm in writing. I summarize decisions so everyone remembers the same thing.

Example

For my Poultry Feed Stock Tracking with POS project, I would explain it to an owner like this: “Poultry feed shops track stock by hand, which causes mistakes. This app updates the stock automatically with every sale, so you always know what is left.”

Where I practiced this

In my mock IT job interview, I explained my projects, skills and career goals out loud. I also document my work, such as my case files and project pages, so other people can follow my reasoning.

Time management

Meeting a deadline is about planning early and avoiding wasted time. This is how I do it.

How I meet deadlines

  1. Break the work into steps. Each project starts with a need, then I split it into small tasks such as design, build, test and document.
  2. Do the core features first. The main function must work before I add extras.
  3. Set smaller target dates for each step instead of one date at the end.
  4. Change one thing at a time when testing, so errors are easy to find and fix.
  5. Save working versions in Git. If a change breaks something, I can go back quickly instead of losing hours.
  6. Leave time at the end to check the work before submitting.

Example

I completed three projects: Poultry Feed Stock Tracking with POS, Social Media Engagement Analysis, and an Expense Tracking Application. Each one needed planning, testing and documentation, so I worked in stages to finish them.

What I learned

Measuring and planning before fixing saves more time than rushing. Small steps and regular checks keep a project on schedule.
